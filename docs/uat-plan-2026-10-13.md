## Why this UAT

Five days put a lot on prod at once: own invoicing (Phases 1–6), group-event
sign-ups, the DJ/makeup/hair launch, the hair and trial fixes, the wedding
planner trade, payment plans, the vendor network (couple's vendor list, the
vendor offer, the vendor database), slot blocking, the studio call alert,
referral partner codes, and the "one source of truth" fix for answers showing
as TBD. Unit tests passed on all of it. The lesson from 2026-09-19
(docs + memory "walk it on prod or it is not done") is that real emails and
real clicks find what tests can't: so every journey below ends in **a real
email read in the inbox** or **the last click of the flow on prod**.

## How we run it

- **Where:** production, `https://studio-cue.com`. Mock walks don't count.
- **Two browsers:**
  - **Claude in Chrome** (Conor's Chrome): the studio side, signed in as the
    test studio for the journey, and the Console as Conor.
  - **The Claude browser pane:** the client and crew side. **Conor signs in**
    as the persona; Claude never types a password or signs in as anyone.
- **Email:** every persona is a plus-address on `conor@flawlessiq.com`, so
  each email can be read through the Gmail connector. An email isn't
  "sent" until it's been read there.
- **Order:** waves, highest risk first. Each journey has an early job and,
  where a step is time-based, a "late twin" dated inside the window (e.g. 9
  days out) so lock-day and reminder steps can run today.
- **Evidence:** a screenshot (desktop **and** phone width for every new
  screen), the email, or the record, per step.
- **Fixing:** a P0/P1 found mid-walk is fixed, deployed and re-walked before
  moving on; P2/P3 are batched at the end of the wave.

### Tool traps (from past walks — not product bugs)

- A Chrome window behind others is a **hidden tab**: scrolling, timers and
  jump links misbehave. Check `location.hash`/state, not scroll position.
- Typing into a field clicked by ref sometimes misses React inputs: click by
  coordinates and read the value back before submitting.
- Right after a functions deploy, 502s until the invoker script runs.
- Chrome sometimes ends up signed in as a test studio rather than the
  Console account: check who's signed in before each wave.
