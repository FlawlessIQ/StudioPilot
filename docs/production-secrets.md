# Production Secrets

StudioCue production uses Google Secret Manager in project `studiohub-prod`.
Provider credentials must be added directly in Google Cloud. Do not place
credential values in chat, source control, App Hosting YAML, Firebase client
configuration, local shell history, or Firestore.

## Provisioning

Create the standard secret containers and resource-level IAM bindings:

```bash
npm run secrets:provision
```

The command is idempotent. It creates secret resources with automatic
replication and grants `roles/secretmanager.secretAccessor` on each implemented
runtime secret to:

```text
988256939236-compute@developer.gserviceaccount.com
```

It does not add versions, print credential values, or grant project-wide Secret
Manager access. App Hosting and the PDF/file-safety workers receive no provider
secret access.

Initialize application-owned secret values:

```bash
npm run secrets:initialize
```

This idempotently creates a cryptographically random
`SENDGRID_INBOUND_TOKEN` version without displaying it. It never replaces an
existing enabled version.

Inspect container, version, and access status without reading values:

```bash
npm run secrets:status
```

## Credential entry

Open the [StudioCue production Secret Manager][secret-manager]. Select a secret,
choose **New version**, paste the exact credential value, and enable the
version. Tell the deployment operator only the secret name that was populated.

[secret-manager]: https://console.cloud.google.com/security/secret-manager?project=studiohub-prod

The following secrets are wired to implemented Cloud Functions:

| Secret | Source | Runtime purpose |
| --- | --- | --- |
| `STRIPE_SECRET_KEY` | Stripe restricted/live API key | Checkout and Customer Portal |
| `STRIPE_WEBHOOK_SECRET` | Stripe webhook endpoint | Signature verification |
| `GOOGLE_CALENDAR_CLIENT_SECRET` | Google OAuth client | OAuth exchange and token refresh |
| `ZOOM_CLIENT_SECRET` | Zoom OAuth app | OAuth exchange and token refresh |
| `DROPBOX_CLIENT_SECRET` | Dropbox OAuth app | OAuth exchange and token refresh |
| `DOCUSIGN_CLIENT_SECRET` | Docusign integration key | OAuth exchange and token refresh |
| `DOCUSIGN_WEBHOOK_HMAC_SECRET` | Docusign Connect | Signature verification |
| `QUICKBOOKS_CLIENT_SECRET` | Intuit developer app | OAuth exchange and token refresh |
| `QUICKBOOKS_WEBHOOK_VERIFIER_TOKEN` | Intuit developer app | Signature verification |
| `SENDGRID_API_KEY` | SendGrid restricted API key | Transactional mail |
| `SENDGRID_INBOUND_TOKEN` | Generated by `npm run secrets:initialize` | Inbound Parse endpoint authentication |
| `SENTRY_DSN` | Sentry server project | Privacy-filtered operational errors |

These containers are reserved but intentionally have no runtime access until
their implementation is activated:

- `INTEGRATION_TOKEN_ENCRYPTION_KEY`

## Nonsecret production configuration

Provider identifiers and routing configuration are not secret versions. They
belong in the ignored `functions/.env.studiohub-prod` or the appropriate
deployed runtime environment:

- Stripe price IDs
- OAuth client IDs and redirect URIs
- Twilio Account SID and Messaging Service SID
- SendGrid verified sender and inbound domain
- Vertex AI project, region, and model names
- Sentry browser DSN

Never add `FIREBASE_SERVICE_ACCOUNT_BASE64` in Google Cloud production. Cloud
Functions and App Hosting use their attached service identities.

## Activation sequence

1. Add secret versions directly in Google Secret Manager.
2. Configure the corresponding nonsecret provider identifiers and callback
   URLs.
3. Run `npm run secrets:status`; the required secrets must show at least one
   enabled version.
4. Deploy only the integration Functions being activated.
5. Reapply private invoker IAM with
   `scripts/configure-production-function-invokers.sh`.
6. Run provider sandbox checks and signed webhook replays.
7. Change provider mode from mock to live only after those checks pass.

Secret rotation adds a new enabled version, deploys or restarts the consuming
runtime where required, verifies provider health, then disables the prior
version. Do not destroy the prior version until rollback is no longer needed.
