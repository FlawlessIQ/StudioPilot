production through Chrome. Scope: everything shipped since 2026-09-21, the

## What the walk found

1. **The register page promised "No card required"** and named a deleted plan.
   False since billing enforcement (09-07); the next screen asks for a card.
2. **The staffing list showed an order the offers did not use.** A
   photographer-only profile displayed as "2" for a videographer role, and the
   reorder arrows never reached the plan — moving a preferred videographer to
   the top changed the list and nothing else.
3. **Cue could never select a package** — its picker omitted the required
   `discount`, so every attempt returned `400 INVALID_COMMAND:discount`.
4. **…and said so in machine code**, via `caught.message.replaceAll("_"," ")`.
5. **Cue dropped every crew flow.** `resolveFlowProjectId` required the whole
   stored project name in the sentence; jobs are filed "<couple> Wedding" and
   operators type the couple. See `fixtures-must-match-real-names`.
6. **The crew picker opened on a hardcoded "Second photographer"**, so asking
   for a videographer ranked the roster for photography and listed the only
   videographer last as "Role or specialty does not match".

Findings 5 and 6 were sequential: fixing 5 made the flow render, which exposed
6 immediately.

## The purge, walked end to end

Refused on the live job — *"Someone is still waiting on this job"* — enforced
server-side as `PROJECT_HAS_LIVE_CREW`, not merely in the UI. Tested instead on
a throwaway job so the live offers survived.

The confirmation is genuinely double: type the exact job name (the button stays
disabled until it matches), then *"Delete … and 3 records now? This cannot be
undone."*

The manifest is **computed, not boilerplate** — it listed 1 audit entry, 1
system event, the job itself, and named the contact whose only job it was. A
Firestore snapshot taken beforehand matched it line for line.

Afterwards: project gone, **zero** records still referencing it (bar the
deliberately protected `projectPurges` receipt), the throwaway contact deleted,
**Erin DeMattia untouched**, and crew/packages/invitations/emails all intact.
The receipt records who, when (4.2s), per-collection counts and contact ids —
so a purge stays auditable after its records are gone.
